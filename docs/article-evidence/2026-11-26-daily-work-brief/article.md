# 让 Grok Bot 每天整理一份工作简报，第一次该怎么设置？

已完成的工作、正在推进的事项和需要确认的问题，往往散落在不同消息中。让 Grok Bot 整理工作简报，先要说清资料来源、保留哪些内容，以及结果交付到哪里。

这次我们在本地 Grok Bot 实际完成了单次整理、创建每日 Routine、换材料试跑和暂停任务。没有连接邮箱、日历或工作群，输入全部是虚构教学记录。你可以先用相同方式练习，再替换成自己允许 Bot 读取的工作来源。

> 本次验证了简报整理和 Routine 创建，但没有验证计划自动触发。当前客户端没有显示 Test 入口，因此后续测试采用对话即时试跑；演示结束后，Routine 已暂停。

## 第一步：先决定简报从哪里取资料

“每天整理工作简报”还不够具体。Bot 需要知道它整理的是哪一份记录、哪些记录需要整理，以及结果发到哪里。

本次选择最容易核对的一种来源：在当前 Bot 对话里提交工作记录。创建 Routine 时，进一步限定只读取明确标为“工作记录”的消息，只整理约定范围内的记录。

| 配置项 | 本次演示的选择 |
| --- | --- |
| 执行者 | 当前主 Bot：Grok Bot |
| 输入来源 | 当前对话中明确标记的工作记录 |
| 交付位置 | 当前对话 |
| 输出内容 | 已完成、进行中、风险与待确认、下一步建议 |
| 没有新记录 | 明确报告，不重复旧简报 |
| 外部操作 | 不发消息、不修改文件、不联系其他 Bot |

如果你的工作资料在其他应用中，应当把具体位置和访问范围交代清楚，再确认 Bot 实际能够读取。不要以为创建了计划，它就会自动知道所有工作进展。本次没有测试任何外部应用的数据连接。


## 第二步：先让它整理一次，不急着设置每天执行

我们向 Grok Bot 提交了一份虚构教学材料，用来检查它是否能合并重复项、保留缺失信息，并区分讨论与已确认任务。

下面是这次指令的整理版：

~~~text
先整理一次工作简报，不创建Routine。
以下为虚构教学记录：

小林已完成FAQ初稿，文档链接暂未提供。
小周校对FAQ进行中，交付要求待确认。
同一条FAQ校对记录重复出现，内容未变。
产品封面待处理，负责人和交付要求未明确。
讨论首页改版，尚未决定实施。

按“已完成、进行中、风险与待确认、下一步建议”输出。
每条事实能对应原始记录，合并重复项。
缺失信息不要猜，讨论不要写成已经决定的任务。
建议与事实分开，只在本对话返回。
~~~

Grok Bot 返回了整理结果。它把FAQ初稿放在“已完成”，把校对放在“进行中”，并合并了重复的校对记录。产品封面的负责人、交付要求，以及初稿缺失的链接，都保留在待确认信息中。

![Grok Bot首次返回的工作简报，保留缺失信息并合并重复记录](https://img.yjfan.top/article-images/2026-11-26/grok-bot-daily-work-brief/grok-execution/01-result-03247840bf67.webp)

*图1：真实单次任务结果，输入为虚构教学材料，截图已裁去私人侧栏。*

首页改版没有被写成已确认待办，而是保留“尚未决定实施”的状态。“请补充链接”“先确定负责人”等内容则放在建议区域。核对时看这些细节，比只看四个小标题是否齐全更有用。

如果第一次结果不符合要求，先纠正整理规则，再重新核对。否则把同一套要求设成每日执行，只会每天重复产生相同的问题。

## 第三步：创建每日 Routine，把无数据的情况也写进去

单次结果符合要求之后，我们继续要求当前 Grok Bot 创建一个名为“每日工作简报（博客演示）”的 Routine。这里没有先创建 Skill，而是直接将整理规则写进例行任务。

下面是便于复用的创建指令，具体运行计划请按自己的工作安排填写：

~~~text
请创建Routine：“每日工作简报（博客演示）”。
由当前Bot负责，每天执行；运行计划按我的实际工作安排设置。

只读取当前对话中我明确标为“工作记录”的消息，
只整理本次需要处理的新记录。
不要把此前的教学样例当作以后每天的输入。

按已完成、进行中、风险与待确认、下一步建议输出。
事实对应原始记录；合并重复项；缺失信息不猜测；
讨论不当作决定；建议与事实分开。

没有符合条件的工作记录时，输出：
“本次没有可用的新工作记录”。不要复制旧简报。

只在当前对话交付，不读取其他私人资料，
不发送外部消息、不修改文件、不联系其他Bot。
创建后告知名称、计划和当前状态，暂不自动测试。
~~~

Grok Bot 返回创建结果，对话里也出现“已创建 例行任务”的记录。回复包含任务名称、运行计划和启用状态。

![Grok Bot返回例行任务创建结果和当前状态](https://img.yjfan.top/article-images/2026-11-26/grok-bot-daily-work-brief/grok-execution/02-created-56729e7fc1f5.webp)

*图2：真实的例行任务创建回复。创建成功不等于自动执行已经验证。*

随后打开 Bot 详情，例行任务列表确实出现了同名任务，开关处于开启状态。这说明计划已在界面中保存，不能据此宣称自动执行已经通过验证。

## 第四步：打开任务核对，而不只看一句“已创建”

核对时至少检查三件事：任务名称是否对应、运行计划是否符合预期、当前开关是否开启。如果计划不对，直接说明要修改哪一个 Routine，避免重复创建同名任务。

本次界面的右键菜单只有“暂停”“编辑”“删除”，没有 Test 按钮。点击任务名称也没有展开可检查完整指令的详情页。因此，输入范围与规则依据创建指令和 Bot 的返回说明记录，未取得独立的完整配置页面来逐项复核。

![每日工作简报在任务列表中显示已开启，右键菜单没有Test](https://img.yjfan.top/article-images/2026-11-26/grok-bot-daily-work-brief/grok-execution/03-menu-7edd7eafd3d3.webp)

*图3：实际客户端界面，右侧显示已创建的任务，菜单仅提供暂停、编辑和删除。*

本次没有找到 Test 入口，因此改为在对话中使用新材料试跑相同的整理规则。即时试跑完成后，首次计划运行仍需单独核对。

## 第五步：换一份工作记录，进行即时试跑

我们另外提交了一份虚构材料，以“工作记录”开头，检查 Bot 是否会正确处理新输入：

~~~text
工作记录（虚构教学数据）：
任务D：帮助页标题校对已完成，负责人小陈。
任务E：替换产品插图进行中，负责人小赵。
任务E：同一条记录重复出现，内容不变。
任务F：补充FAQ链接待处理，负责人和交付要求未明确。

请尝试立即测试已创建的例行任务，不要新建第二个。
若无法立即触发，就按相同规则在本对话试跑一次，
明确标注“即时试跑，非定时触发”。
~~~

Bot 返回说明，它没有立即触发已有 Routine 的工具，所以本次是在对话中按相同规则执行。它交付了新简报，并明确标注“即时试跑，非定时触发”。

![Grok Bot用第二份材料即时试跑，明确说明不是定时触发](https://img.yjfan.top/article-images/2026-11-26/grok-bot-daily-work-brief/grok-execution/04-trial-c52d14df3b76.webp)

*图4：新简报使用了小陈、小赵与任务D、E、F，没有沿用第一份样例中的人物和任务。*

输出中，任务D归入已完成；任务E归入进行中，重复项被合并；任务F仍保留负责人和交付要求未明确的状态。新结果对应这份输入，没有直接复制前一份简报。

这次试跑验证了新材料的整理表现，但没有验证 Routine 调度器自动启动，也没有验证系统能在大量历史消息中始终准确筛选符合条件的记录。实际长期使用时，仍要检查首次计划执行及后续结果。

## 第六步：检查没有新记录时会怎样

没有新材料时，简报不应该把旧内容原样再交一遍。我们额外提出一个假设：没有符合条件的新工作记录，请按规则返回空数据提示。

Bot 返回：“这是对话即时试跑，不是定时触发。本次没有可用的新工作记录。”没有重新输出前面的任务列表。

这只是人为指定无输入条件的一次分支演示，不能据此判断它已经验证了实际输入筛选。它的价值是检查：无数据时需要返回的文字已经说清楚，而且 Bot 在当前测试中遵守了要求。

## 演示结束后，暂停不再需要的任务

为了不让教学任务继续每天运行，我们随后要求只暂停“每日工作简报（博客演示）”，保留任务，不修改其他 Routine。

Bot 返回暂停结果后，我们再次打开列表：同名任务显示“已暂停”，开关关闭。这一步有实际界面佐证。

![空数据分支回复与每日工作简报已暂停的任务开关](https://img.yjfan.top/article-images/2026-11-26/grok-bot-daily-work-brief/grok-execution/05-paused-1e7d3f205a4d.webp)

*图5：右侧任务显示已暂停，左侧对话保留空数据分支及暂停结果。*

如果你确实要长期使用，应在输入来源、访问条件和简报格式核对完成后启用，检查第一次计划运行，再决定是否调整运行计划。

## 这次实际验证到了哪一步

| 环节 | 实际结果 |
| --- | --- |
| 单次简报 | 已返回，重复项合并，缺失信息保留 |
| 每日Routine创建 | 已创建，任务列表曾显示启用 |
| Test按钮 | 当前客户端未显示，Bot也表示无法立即触发 |
| 新材料测试 | 已完成对话即时试跑，不是定时触发 |
| 无新记录处理 | 已完成假设条件下的对话分支演示 |
| 计划自动触发 | 未验证；演示任务已暂停 |
| 最终状态 | 列表显示已暂停，未删除 |

第一次设置每日简报，可以从一份短记录开始。先核对结果，再保存计划，然后检查实际运行。任务能否持续有用，取决于输入是否持续更新、输出能否回查，以及没有新资料时是否如实说明。

想了解任务为什么可能持续消耗用量，可以阅读[用量排查](/article/grok-bot-usage-troubleshooting/)；若客户端显示缓存消息、连接应用无法加载，可以对照[连接与Skill排查](/article/grok-bot-skill-not-found-connection-troubleshooting/)。
